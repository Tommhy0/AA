# 用剧情证据保持角色一致

用户选择：默认使用方案二（已有剧情证据档案），方案三（查询原文）只在需要时启用。以角色动机、说话方式、关系与剧情阶段支持创作，避免把性格写成固定禁令。合时宜的语气气泡仍鼓励作为点睛。

## 默认：读取本次出场人物的档案

1. 通过 [学生索引](characters/INDEX.md) 或 `character_tool.py list` 确认名字、别名和基础 ID。索引收录 135 个文本角色名、244 个版本 ID；其中 72 名有初版证据档案，其他项只有资料定位，不能声称已经分析性格。角色库 ID 用来选剧情资料，不是 AzureArchive 的资源键或栏位 ID。
2. 只读取出场学生的卡，核对基础定位、语气、情境反应、人物关系与阶段边界。明确设定、场景事实和写作归纳分开理解；一个场景的反应不自动推广为所有场景。
3. 明确本篇发生的阶段、角色彼此的关系与已经知道的信息。用户未指定时可按基础日常写作，不擅自加入后期秘密、成长后的关系或新设定；若时间点直接影响剧情，先说明假设或澄清必要信息。
4. 写作完成后复核动机与行为是否吻合、措辞与称呼是否符合对象、知识是否超过当时认知、关系变化是否有铺垫、表情/动作/气泡是否合时宜。保留有依据的反差和成长，不为保持几个标签抹掉角色的主动性。

读取现成卡不依赖网络，也不需加载原文库：

```powershell
python -B -X utf8 scripts/character_tool.py list --query "白子"
python -B -X utf8 scripts/character_tool.py profile "白子"
python -B -X utf8 scripts/character_tool.py profile "日奈"
```

中文常用名、部分旧译名、日文名及基础角色 ID 可以定位。明确衣装名/ID 会显示基础卡并提示其衣装尚未单独归纳，不自动声称共享所有心理状态。名字冲突或未知时不猜选；用 list 查确切名字/ID。

## 按需：用原文解决一个具体问题

以下情况值得检索：没有现成卡；需要未覆盖的重要关系或成长阶段；角色作重大决定；两份资料矛盾；用户质疑 OOC 或明确要求原作对照。普通日常若卡已足够，不默认通读全量剧情、重新生成全部档案或安装额外角色扮演技能。

先写清待核对的问题，例如“此时她是否已信任老师”“她如何称呼这位前辈”。按人物、类别、关键词和版本 ID 定位，读取相邻对话与该场景的因果，再决定是否扩展；避免凭一句话或出现频率判断。关键词是原文关键词，不是自动翻译的中文检索或向量语义搜索。

```powershell
python -B -X utf8 scripts/character_tool.py search "星野" --category bond --character-id 10005 --keyword "鯨" --limit 4
python -B -X utf8 scripts/character_tool.py search "弥香" --category main --keyword "聴聞" --limit 4 --context 6
python -B -X utf8 scripts/character_tool.py search "白子（泳装）" --category bond --limit 4
```

`--category` 支持 bond/main/event/club/momo/profile/mini。默认最多返回 6 条，`--limit` 可设 1–20，`--context` 是周边原文件行数（默认 3，最多 6）。返回结果只是定位，必要时打开对应文件扩大上下文。`--character-id` 仅匹配文件中确有该 ID 的材料；主线通常没有角色 ID 元数据，不能以此字段判断主线时间点，也不要将查无结果当作“原作没有”。不设 ID 时结果可能混有不同衣装，必须看元数据。

每条结果给出文件、行号、上下文、SHA-256 和快照匹配状态。只有本地文件与固定快照哈希一致时，才返回对应提交的 GitHub 行链接；文件有变化时重新核对，不能沿用旧结论。

## 原文位置与离线退路

完整语料保留在技能之外的本地缓存。工具查找当前工作目录及上级目录下 `.aa-character-cache/ba-storybook/ba-stories`，也可明确指定：

```powershell
python -B -X utf8 scripts/character_tool.py search "星野" --category bond --corpus "资料目录/ba-storybook/ba-stories"
python -B -X utf8 scripts/character_tool.py verify --corpus "资料目录/ba-storybook/ba-stories"
```

环境变量 `AZUREARCHIVE_CHARACTER_CORPUS` 可设为语料目录。设置了显式位置但不可用时报告失败，不悄悄换到另一个版本。工具不自动下载、不调用付费 API、不运行上游技能。没有本地语料时仍可使用卡；需要补查时沿卡的固定提交链接读取相关页面。若还无资料，说明具体缺口，避免编造人格、关系或剧情。

源仓库：[HePudding/ba-storybook](https://github.com/HePudding/ba-storybook)。本库固定提交 `6c4091603ca76d7d8c3cdb9104933f52cd8cab8e`，上游数据日期 2026-04-22，取得日期 2026-10-10；不代表实时完整覆盖。换用新语料前检查对应材料差异，重新确认受影响的结论和出处，保留旧版可追溯信息。

## 证据取舍与 OOC 复核

- 优先使用游戏简介与剧情中有上下文的实际表现；社区解释可作线索，二创梗不能直接变成原作事实。中文表述保留意味和称呼关系，不强行照搬日文敬称、语尾或一句口癖。
- 同名、不同衣装、低年级与成长后的阶段分开。涉及剧情秘密、师生信任、政治身份时优先看所写阶段。不能从基础性格推出角色当时已经知道的信息。
- 同一个人面对不同对象可以有不同语气。礼貌不是永远附和，内向不是永远结巴，能力出众不是全知，善意也不意味着不会冲动、误判或越界。
- 上游部分分支有重复台词，部分 MomoTalk Answer 区和其他对话的说话人标注可疑。检索默认排除 Answer 区；其他文本仍结合语义核对，不能只按标签自动归纳口癖、将玩家选项计入学生台词，或把重复分支当成习惯的多重证据。
- 有疑点时定位具体台词/行为，并提出符合既定情境的修改。无证据的私人喜好、恋爱状态和关系判断保留不确定；用户明确的平行设定可优先采用，但不要称其为原作。
- `verify` 只验证本地材料哈希、证据行范围与对应版本；`aa_tool.py validate/compile` 验证工程和资源。它们都不证明无 OOC。需要人物复核时用实际场景和证据说明，不能报告一个无依据的“全角色检查通过”。
